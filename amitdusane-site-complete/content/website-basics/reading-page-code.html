Why it matters to you

A developer sends you a few lines of code and asks whether it is what you wanted. You will never write JavaScript, but you can learn to read these lines in an afternoon. Most tracking code uses the same few shapes, and once you know them, a reply replaces a meeting.

An object is a form with labelled boxes

An object is a set of named values inside curly brackets. Think of a paper form: the label is printed on the left, and what was written in is on the right.

{
  page: "product",
  productId: "SKU-1042",
  price: 49.99,
  inStock: true
}

Each line is a name, a colon and a value, and the lines are separated by commas. Text inside quotes is a string. A number without quotes is a number. The words true and false, without quotes, mean yes and no.

An array is a list

An array is a list of values inside square brackets. The values can be strings, numbers or whole objects.

products: [
  { id: "SKU-1042", quantity: 1 },
  { id: "SKU-2210", quantity: 2 }
]

This basket holds two products. Programmers count from zero, so products[0] is the first product and products[1] is the second. When a developer says "item zero", they mean the first one.

A function call does something

A function is a named action. A name followed by round brackets calls it, and whatever sits inside the brackets is what the function is given to work with. These three calls are the ones you will meet most in Adobe tracking.

window.adobeDataLayer.push({ event: "addToCart", product: { id: "SKU-1042" } });

alloy("sendEvent", { xdm: { eventType: "commerce.productListAdds" } });

_satellite.track("add-to-cart");
adobeDataLayer.pushAdds an object to the Adobe Client Data Layer. The tag manager can react to it.
alloy("sendEvent")Sends an event to Adobe directly, using the Web SDK.
_satellite.trackTells Adobe Tags to run the rule set up for that name.

An event listener says when

An event listener is code that waits for something to happen and then runs.

button.addEventListener("click", function () {
  _satellite.track("add-to-cart");
});

Read it as a sentence: when this button is clicked, run the add-to-cart rule. The first word inside the brackets names the moment. That moment is often the most important thing to check, because a call sent at the wrong moment sends the right values at the wrong time.

A number in quotes is not a number

price: 49.99 is a number. price: "49.99" is text that looks like a number. Some systems accept either. Others reject the wrong one, or store it where you do not expect. Adobe Experience Platform checks this strictly: a field defined as a number that receives text is rejected.

JSON is the text format used to send objects and arrays between systems. It uses the same shapes, with every name in double quotes. When a developer sends you JSON, read it exactly as you would read the object above.

What you can ignore

Much of the code on a page is not for you. Lines that start with //, and text between /* and */, are comments. They are notes for developers, and the browser skips them. Lines with console.log only print messages in the console.

Code on a live site is often minified: squeezed onto one very long line, with short names such as a and b, so that it downloads faster. You are not expected to read it. In the developer tools, the Sources tab has a button marked with curly brackets that spreads it back into readable lines. For a tracking question, ask the developer for the readable version instead.

Three questions for any snippet

Before you reply

When does it run? Which values does it send? Where does each value come from: the page, the server or the visitor? If you can answer all three, you understand the snippet well enough to approve it or correct it.
