A browser consent banner appears on a page that has usually already loaded, and a returning visitor carries a cookie that answers the question before it is asked. An app has neither. The first launch is a person opening something they just downloaded. No stored preference, no prior page. And the SDK starts sending events the moment it initialises. So the decision that matters is not which banner to build. It is what the SDK does in the seconds before anybody has answered, and that is a setting rather than code.

Set the default first
1
Where Data Collection › Tags › your mobile property › Extensions › Consent for Edge Network
Do Set Default Consent. Pending holds events in a queue until a person answers. Yes collects immediately. No collects nothing until told otherwise.
2
Do Publish the library. This is a property setting, so it changes without an app release, which makes it one of the few things here you can correct quickly.

Choose Pending unless somebody with legal responsibility has told you otherwise in writing. It is the only default that neither discards a first session nor collects before permission. Events queue. They are sent or dropped once the answer arrives. Yes is defensible in some markets and indefensible in others, which is not a judgment to make on a developer's behalf.

Record the answer when it comes
iOS · Swift
let collectConsent = ["collect": ["val": "y"]]
let currentConsents = ["consents": collectConsent]

Consent.update(with: currentConsents)
Android · Kotlin
val collectConsents = mutableMapOf<String, Any>()
collectConsents["collect"] = mutableMapOf("val" to "y")

val consents = mutableMapOf<String, Any>()
consents["consents"] = collectConsents

Consent.update(consents)

Sending n instead of y records a refusal, and it has to be wired up with the same care as the acceptance. An app that records only agreement has not implemented consent. It has implemented a button that sometimes does nothing.

Where this goes wrong

The default is left at Yes because it was the value that made testing easy, and nobody revisits it before release. Every first launch is then collected before the person has been asked, in every market, and the fault is invisible in reports because the data looks complete. Complete data is exactly what the failure produces.

✓ Ready when

The default is set deliberately and somebody other than you has agreed it. Both answers are wired, not only the yes. A refusal on first launch results in no events reaching the Edge, and you have watched that happen rather than assumed it.
