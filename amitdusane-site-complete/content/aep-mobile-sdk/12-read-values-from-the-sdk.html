Sooner or later a meeting happens where the app team believes tracking is working and the numbers say it is not, and neither side can prove anything. On the web that argument lasts a minute, because somebody opens a console. In an app there is nothing to open. What there is instead is a set of calls that ask the SDK for its own state. A developer can put those behind a hidden debug screen in an afternoon. That screen is worth more to you than any dashboard, because it ends the argument with a value rather than an opinion.
Why?Why does it sometimes come back empty? ↗What should the ECID look like? ↗
The three questions worth asking
getExperienceCloudIdIs the SDK initialised at all? An ECID exists from first launch. No ECID means nothing else is worth checking.
getIdentitiesIs your customer ID actually attached, on the namespace you agreed? This is the cross-channel question.
getConsentsWhat does the SDK believe it is allowed to do? An unexpected value here explains most cases of missing data.
Reading them
iOS · Swift
Identity.getExperienceCloudId { ecid, error in
    print("ECID: \(ecid ?? "none")")
}

Identity.getIdentities { identityMap, error in
    print("Identities: \(String(describing: identityMap))")
}

Consent.getConsents { consents, error in
    print("Consents: \(String(describing: consents))")
}
Android · Kotlin
Identity.getExperienceCloudId { ecid ->
    Log.d("Adobe", "ECID: $ecid")
}

Identity.getIdentities { identityMap ->
    Log.d("Adobe", "Identities: $identityMap")
}

Consent.getConsents { consents ->
    Log.d("Adobe", "Consents: $consents")
}

Every one of these hands its answer to a callback rather than returning it.[6] That is not a style choice. The SDK may still be starting up, and a value that does not exist yet cannot be returned on the spot. Code written as though these return immediately will read an empty value, and it will do so intermittently, which is the worst way for a bug to behave.

Where this goes wrong

The debug screen is built, the ECID shows, and everybody declares the implementation sound. The ECID proves the SDK started and nothing more. It is present on an app with no events, no consent and no customer ID. Treat it as the first of three checks rather than the whole of one.

✓ Ready when

A hidden debug screen shows all three values, and you have seen them on a real device rather than in a screenshot. Ask for it early. It costs a developer an afternoon and it saves whole meetings later, which is a trade nobody regrets.
