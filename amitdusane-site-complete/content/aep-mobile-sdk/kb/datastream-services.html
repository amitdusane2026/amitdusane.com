The most useful thing about the datastream is that the app has never heard of it.

An app sends one XDM event to the Edge Network. The datastream is the setting on Adobe’s servers that receives it and decides what happens next, and it can hand the same event to more than one service.

Add the Adobe Analytics service with a report suite ID and the event reaches Analytics. Add the Adobe Experience Platform service with a dataset and the same event also lands where Customer Journey Analytics can read it.

Neither addition changes a line of app code. That is the point, and it is worth pausing on if you are used to the older mobile model where the destination was built into the app. Routing has moved from the slowest place to change to one of the fastest.

Three datastreams, one per environment, is what keeps test traffic out of live reporting. Development and staging point at a validation report suite throughout. Only production carries the live one.

For your implementation: when a destination is wrong, fix the datastream before anybody looks at the app. Four of the five places an event can go missing are on this side of the line, and this is the cheapest of them to correct.

⚑ Architect’s Decision

Add both services on day one even if Customer Journey Analytics is a year away. The dataset costs nothing while it waits, and history that was never collected cannot be recovered later.
