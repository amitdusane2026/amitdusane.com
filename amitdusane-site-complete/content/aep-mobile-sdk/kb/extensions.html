The extension catalogue is long, most of it belongs to products you are not implementing, and installing extras is not free.

Four cover an Edge Network implementation. Adobe Experience Platform Edge Network is the one that sends events, and it is where you select the datastream for each environment. Identity for Edge Network manages the ECID and any identifiers you add, and the Edge extension will not operate without it, so the two are one decision rather than two. Consent for Edge Network carries the collect preference and holds the default that applies before anybody has answered. AEP Assurance is how you see inside a running app, which on mobile is not optional.

Mobile Core is always present and is not something you install. Lifecycle rides along with the modern initialiser.

Everything else in the catalogue belongs to a product: Messaging, Optimize, Places, Target. Each adds size to the app and configuration to maintain, and a mobile developer will reasonably ask why an analytics project is enlarging their binary. Add them when the product they serve is actually being implemented.

For your implementation: ask for four, name them exactly, and resist adding a fifth speculatively. Extensions are added later without difficulty, and every one you carry unused is weight somebody else is paying for.

⚑ Architect’s Decision

Four extensions, and Assurance is one of them from day one rather than added when something breaks. Retrofitting it during an incident means waiting for a release at the worst possible moment.
