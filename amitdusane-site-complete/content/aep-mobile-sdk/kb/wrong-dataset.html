The confusing version of missing data is not an error. It is a report that stays empty while Assurance insists everything was accepted.

When the Edge accepts an event and the report does not show it, the event went somewhere. Four causes account for nearly all of it, and all four are settings rather than code.

The environment may be wrong: a build carrying the development Environment File ID reports through the development datastream, into a validation report suite, exactly as designed. The service may be missing: a datastream with only the Analytics service sends nothing to any dataset, and Customer Journey Analytics stays empty while Analytics looks perfect. The dataset selected may be a different one from the one being queried. Or the report suite on that datastream may not be the one open on your screen.

None of these produces a warning, because none of them is a fault. The pipeline is doing exactly what it was configured to do, and the configuration is the thing that is wrong.

For your implementation: when data is accepted but absent, read the datastream for the environment the build is actually using, rather than the one you were thinking of. That single check resolves most of these in a minute.

⚑ Architect’s Decision

Write down which Environment File ID, datastream, report suite and dataset belong to each environment, and keep it where the whole team can see it. Most of this class of problem is caused by two people holding different versions of that mapping in their heads.
