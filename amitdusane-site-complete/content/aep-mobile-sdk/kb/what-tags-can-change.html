The useful question is not whether you can change something without a release. It is which things, and the list is shorter than the web one and a good deal longer than nothing.

Start with what travels freely. The property is fetched by the SDK when the app launches, so anything held in it reaches phones that are already installed, with nobody shipping anything. Which datastream each environment talks to. Which extensions are switched on, and what each one is configured with. The default consent value. The lifecycle session timeout. All of that is yours, in a browser, this afternoon.

It also holds rules, which surprises people who have been told that mobile has none. Two actions matter for measurement. Attach Data adds values to an SDK event and never overwrites: where the rule and the event disagree, the event wins. Modify Data is the stronger one and can add, change or remove values, overwriting where they conflict.

Then the limit, which is the part worth memorising. A rule can only act on an event the app already fires. It cannot invent an event the app never sends. It cannot read a data layer, because there is none. It cannot reach a value the app never put anywhere. Everything a rule works with is already on the event, already in the SDK's own shared state, or typed into the rule as a constant. It decorates; it does not originate.

Which turns "can we add this in Launch" into a question back, and the question is always the same one. Is the value already on an event that already fires? If it is, then often yes. If it is not, then never, and what the request actually needs is a developer and a release.

For your implementation: ask that question before promising anything to anybody. The gap between "we can do that in the tag property" and what the tag property can do is where three weeks disappear.

⚑ Architect’s Decision

Push every decision you can into the tag property and the datastream, and none that you cannot. The test has not changed: if getting it wrong would need a release to fix, it is in the wrong place.
