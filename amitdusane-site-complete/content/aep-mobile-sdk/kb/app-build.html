A web page is delivered as the text somebody wrote. An app is delivered as a sealed object made from that text, and the text is nowhere inside it.

Building is translation. A developer writes Swift or Kotlin, and a compiler turns it into machine instructions packaged with images, fonts and configuration into one file. That file is what reaches a phone. It cannot be opened and read, it cannot be edited in place, and there is no equivalent of view-source pointed at it.

Everything awkward about mobile measurement descends from that. There is no console to paste a check into, no network tab listing requests, and no way to confirm from the outside that a tracking call exists. The only way to see inside a running app is a tool the app itself invites in, which is what Assurance is.

It also explains the waiting. Changing one string means a new build, and a new build means the whole file is made again, tested again, and submitted again. The cost is the same whether the change is one character or one thousand lines, which is why developers batch changes and why your small request joins a queue rather than jumping it.

For your implementation: stop asking whether something is in the code and start asking which build it is in. Those are different questions with different answers, and only the second one can be tested.

⚑ Architect’s Decision

Treat every request as costing a release, and batch accordingly. Ask for the tracking you need in one specification rather than in six tickets across a quarter.
