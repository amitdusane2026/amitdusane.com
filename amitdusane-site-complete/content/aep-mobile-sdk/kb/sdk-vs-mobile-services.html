Search for Adobe mobile tracking and you will find three products with similar names. Two of them are retired, and all three are still documented somewhere.

AppMeasurement and the older Adobe Mobile Services SDK belong to the previous generation. They think in context data: a flat bag of keys sent with a hit, turned into eVars and props by processing rules on the Adobe side. Many production apps still run this, and it still works.

The Adobe Experience Platform Mobile SDK is the current one, and it is a set of extensions rather than a single library. Sending data through its Edge Network path means sending XDM: a defined schema with typed, nested fields agreed before any data moves.

That is a different model, not a renamed one.

The confusion is worth naming, because the older material is still the first result for many searches. Code samples calling trackAction with a context data dictionary are almost always from that earlier world. Copying them into a new implementation produces something that works and is shaped wrongly for anything beyond Adobe Analytics.

For your implementation: establish which one the app has before planning anything. An app on the old SDK is a migration. An app with no SDK is a fresh build. Those are different projects with different lengths.

⚑ Architect’s Decision

For anything new, the Experience Platform Mobile SDK on the Edge Network path, sending XDM. The older model is only right when you are keeping an existing implementation alive rather than building one.
