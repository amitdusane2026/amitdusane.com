On the web a rule reads the page and builds what gets sent. A mobile app has no page to read, so something else has to supply every value.

Start with the web model, because the contrast is the whole answer. A data layer sits on the page, holding values the page has published about itself. A rule in the tag property reads it, builds XDM from what it finds, and hands that to the SDK.

Three parties: the page publishes, the rule builds, the SDK sends. The middle one belongs to the analytics practitioner, which is why that work has always felt like theirs to do.

There is no data layer on mobile. Nothing publishes values into a place a rule could read, because there is no page and no document.

The app builds the XDM itself and hands it to Edge.sendEvent. Every value in that payload exists because a developer wrote it into the call, and it exists nowhere else.

A second path carries the old vocabulary, and it is worth knowing. An app already calling MobileCore.trackAction or trackState can keep calling them, and the Edge Bridge extension forwards those calls to the Edge Network instead of to the old Analytics extension. Their context data lands in the event’s data node rather than in XDM, and Data Prep on the datastream maps it onward from there.

So context data did not disappear on mobile. It moved to the datastream.

And the answer to whether there is a rule for each event, the way there is on a website, is no. That is not an inconsistency somebody failed to tidy up. A browser has a page to read and an app does not, and everything else follows from that one difference.

For your implementation: find out which of the two paths the app is on before you specify anything. It decides whether your list of fields goes to a developer and waits for a release, or goes into a datastream mapping and is live this afternoon.

⚑ Architect’s Decision

If an app is already sending context data through Edge Bridge, do not rewrite it into native XDM for tidiness. The mapping is on the server and changeable; the rewrite is a release, and it buys nothing a reader of the dataset can see.
