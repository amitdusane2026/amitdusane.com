Asking a developer to add a log line works once, costs a build, and answers only the question you thought to ask.

A log line is written in advance by somebody guessing what will matter later. It shows the app’s own account of itself: this function ran, this value was set.

That account is honest and incomplete, because it stops at the edge of the app. Everything interesting happens after that.

Assurance connects to a running app and shows the whole path: every event the SDK raises, whether it left the phone, what the Edge Network made of it, and what came back, including a rejection and its reason. It arrives through an extension already in your property, so there is no build to wait for.

The practical difference is the third column of the event view. An event visible on the client proves the tracking code ran, which is what a log line would have told you. An event reaching post-processed data proves the Edge accepted it, which is what anybody meant by asking whether tracking works.

For your implementation: get Assurance working before you need it. Adding it during an incident means waiting for a release at the worst possible moment, and that wait turns a two-hour problem into a two-week one.

⚑ Architect’s Decision

Assurance goes in the first extension list, not the second. An implementation without it is one where every future question costs a build.
