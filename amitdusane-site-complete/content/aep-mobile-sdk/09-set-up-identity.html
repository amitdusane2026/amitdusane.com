The SDK creates an ECID on first launch and attaches it to everything, with no work from anybody.

That is useful, and it is also the source of the most persistent misunderstanding in mobile analytics. An ECID identifies an installation, not a person. The same person on a phone and a laptop is two ECIDs. The same person after a reinstall is two ECIDs.

Every question that begins “how many customers” meets that problem.
Why?What survives a reinstall? ↗Why is the ECID not enough? ↗

Nothing on the left is wrong. Each ECID is doing its job correctly. The shared identifier is the only thing that turns three device histories into one customer.

Send your own identifier

iOS · Swift

let identityMap = IdentityMap()
let item = IdentityItem(id: "cust-8842190",
                        authenticatedState: .authenticated,
                        primary: false)
identityMap.addItem(item: item, withNamespace: "CustomerID")
Identity.updateIdentities(with: identityMap)

Android · Kotlin

val item = IdentityItem("cust-8842190",
                        AuthenticatedState.AUTHENTICATED,
                        false)
val identityMap = IdentityMap()
identityMap.addItem(item, "CustomerID")
Identity.updateIdentities(identityMap)

React Native · JavaScript

import { Identity, IdentityMap, IdentityItem }
  from '@adobe/react-native-aepedgeidentity';

const item = new IdentityItem("cust-8842190");
const map = new IdentityMap();
map.addItem(item, "CustomerID");
Identity.updateIdentities(map);

Flutter · Dart

import 'package:flutter_aepedgeidentity/flutter_aepedgeidentity.dart';

IdentityItem item = new IdentityItem("cust-8842190");
IdentityMap identityMap = new IdentityMap();
identityMap.addItem(item, "CustomerID");
Identity.updateIdentities(identityMap);

Three things you decide, not the developer

NamespaceMust be the same string the website sends, or the two channels never join.
The valueMust be the identifier your business already uses, not one invented for analytics.
Auth stateA real claim about whether this person proved who they are. It should be accurate rather than always set to authenticated.
Where this goes wrong

The app sends a customer ID and the website sends the same value under a different namespace. Both implementations pass their own tests, both look correct on their own, and the profiles never join. Agree the namespace once, in writing, before either side builds anything.

If the app has WebView screens

A WebView is a browser, so it gets its own ECID and one person becomes two. Joining them is one call on the app side and nothing at all on the web side, and it is the whole of Measure WebView screens. If you do not yet know whether the app has any, settle that before you finish this step rather than after.

✓ Ready when

The ECID is present on every event, and a customer ID is sent on the same namespace the web implementation uses, at the moment somebody signs in. Removing it on sign-out matters just as much, and is the half people forget.
