There is one API for this, and it takes one argument. Everything the app reports beyond lifecycle goes through Edge.sendEvent carrying an ExperienceEvent, and an ExperienceEvent is XDM: the field names agreed in the schema, filled in with values. No trackAction, no trackState, no context data bag. That is the shift a web practitioner has to make. It is easier here than anywhere else, because the schema has already decided what the field names are.

Sending an event
iOS · Swift
var xdmData: [String: Any] = [
    "eventType": "application.interaction",
    "appInteraction": [
        "name": "add_to_basket"
    ]
]

let event = ExperienceEvent(xdm: xdmData)
Edge.sendEvent(experienceEvent: event)
Android · Kotlin
val xdmData = mutableMapOf<String, Any>(
    "eventType" to "application.interaction",
    "appInteraction" to mapOf(
        "name" to "add_to_basket"
    )
)

val event = ExperienceEvent.Builder()
    .setXdmSchema(xdmData)
    .build()

Edge.sendEvent(event) { }

The shape is the same on both platforms because the shape is the schema.[5] A developer writing this does not invent field names, and that is the point of having done the schema first. What they need from you is the exact path and the exact value, written down.

How to specify one, so it cannot be guessed wrong
1
Give The eventType string, exactly. application.interaction is not the same as application.Interaction.
2
Give The full field path from the schema, not a description of it. appInteraction.name, not “the interaction name field”.
3
Give The exact value, and say whether it is fixed or comes from the app. add_to_basket is fixed; a product ID is not.
4
Give Where in the app it fires, in words a developer can act on: after the basket call succeeds, not when the button is tapped.
Where this goes wrong

The event fires on the tap rather than on success. Every abandoned or failed action then counts as a completed one, the number runs consistently high, and it agrees with nothing in the order system. This is the most common specification failure in app tracking. It is caused by a ticket that said “track add to basket” and stopped there.
