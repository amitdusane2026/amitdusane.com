Everything so far has described data. The datastream is the first thing that moves it.

It sits on Adobe’s servers rather than in the app. It receives every event the SDK sends, then decides where each one goes. One event can land in two places, and that decision is made here rather than in the app, so it can be corrected later without a release.

Build it
Three datastreams, because you will want somewhere safe to test.
1
Where Data Collection › Datastreams › New Datastream
Do Create three: Development, Staging, Production. Point each at the schema from Create the XDM schema.
2
Do On each, Add Service › Adobe Analytics and enter the report suite ID. On Development and Staging that must be a validation suite, never the live one.
3
Do On each, Add Service › Adobe Experience Platform and select the dataset. This is the half that feeds Customer Journey Analytics[22].

The app is deliberately ignorant of destinations. Adding, removing or repointing a service is a change on Adobe’s side, so a mistake here costs an afternoon rather than a release.

Where this goes wrong

Only the Adobe Analytics service gets added, because that is the familiar half. Everything looks correct for months and the reports fill up. Then somebody asks for Customer Journey Analytics and finds no dataset has ever received a row. The app needs no change to fix it. The months of history cannot be recovered.

✓ Ready when

Three datastreams exist, each carrying both services, and the development one points at a validation report suite. Copy the Development datastream ID somewhere you can find it, because the tag property asks for it next.
