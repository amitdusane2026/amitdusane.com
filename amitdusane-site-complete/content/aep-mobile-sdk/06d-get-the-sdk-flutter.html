A Flutter app is written once, in a language called Dart, and produces both the iPhone and the Android app.

Adobe ships a set of plugins that wrap the same native SDK underneath. So everything on the Adobe side behaves exactly as it does for a native app, and your request is built once rather than twice.

The packages

Five packages, added to pubspec.yaml with Flutter’s own tool.

flutter pub add flutter_aepcore
flutter pub add flutter_aepedge
flutter pub add flutter_aepedgeidentity
flutter pub add flutter_aepedgeconsent
flutter pub add flutter_aepassurance

Lifecycle is inside the core package, so there is nothing separate to add.

✓ No native code, since version 5

Worth knowing, because older guides say otherwise. From version 5 of the Flutter plugins there is no need to start the SDK in the native iOS or Android files. Everything happens in Dart. On version 4 and earlier a developer had to edit AppDelegate and the Application class too, and that second half is where implementations used to be left half-finished.

Starting the SDK

import 'package:flutter_aepcore/flutter_aepcore.dart';

MobileCore.setLogLevel(LogLevel.debug);
MobileCore.initializeWithAppId("YOUR_ENVIRONMENT_FILE_ID");

Put that where the app starts, before the first screen is drawn. An event fired before the SDK is ready is not queued and not retried.

The one risk cross-platform adds

The plugins wrap the native SDK, and a wrapper can fall behind the thing it wraps. When Adobe ships something new, the native SDK gets it first and the plugins follow, usually within weeks.

In practice this rarely causes trouble. Everything this guide needs has been supported for years: sending events, identity, consent, lifecycle and Assurance.

It becomes a problem only when somebody wants a newer or unusual feature, and it becomes a problem late, after the schema is agreed.

Where this goes wrong

The team is on version 4, where native startup was still required, and follows a guide written for version 5. The Dart call is added and the native half is not. The app builds, runs, and sends nothing, and the code looks complete to everybody reading it. Confirm the plugin version before anybody follows any instructions, including these.

✓ Ready when

The five packages are in pubspec.yaml, the SDK is started in Dart with the development Environment File ID, and SDK logs appear at debug level when the app launches. Then continue at Turn on lifecycle.
