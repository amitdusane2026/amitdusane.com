A browser consent banner appears on a page that has usually already loaded, and a returning visitor carries a cookie that answers the question before it is asked.

An app has neither. The first launch is somebody opening a thing they just downloaded: no stored preference, no earlier page. And the SDK starts sending events the moment it starts.

So the decision that matters is not which banner to build. It is what the SDK does in the seconds before anybody has answered, and that is a setting rather than code.

Do Set Default Consent. Pending holds events in a queue until somebody answers. Yes collects immediately. No collects nothing until told otherwise.
2
Do Publish the library. This is a property setting, so it is one of the few things here you can correct quickly.

Choose Pending

Choose Pending unless somebody with legal responsibility has told you otherwise in writing.

It is the only default that neither discards a first session nor collects before permission. Events queue, and are sent or dropped once the answer arrives.

Yes is defensible in some markets and indefensible in others, which is not a judgment to make on a developer’s behalf.

Record the answer when it comes

iOS · Swift

let collectConsent = ["collect": ["val": "y"]]
let currentConsents = ["consents": collectConsent]
Consent.update(with: currentConsents)

Android · Kotlin

val collectConsents = mutableMapOf<String, Any>()
collectConsents["collect"] = mutableMapOf("val" to "y")
val consents = mutableMapOf<String, Any>()
consents["consents"] = collectConsents
Consent.update(consents)

React Native · JavaScript

import { Consent } from '@adobe/react-native-aepedgeconsent';

const consents = { "consents": { "collect": { "val": "y" } } };
Consent.update(consents);

Flutter · Dart

import 'package:flutter_aepedgeconsent/flutter_aepedgeconsent.dart';

Map<String, dynamic> consents = {
  "consents": {"collect": {"val": "y"}}
};
Consent.update(consents);

Sending n instead of y records a refusal, and it has to be wired up with the same care as the acceptance. An app that records only agreement has not implemented consent. It has implemented a button that sometimes does nothing[7].

Where this goes wrong

The default is left at Yes because it was the value that made testing easy, and nobody revisits it before release. Every first launch is then collected before the person has been asked, in every market, and the fault is invisible in reports because the data looks complete. Complete data is exactly what the failure produces.

✓ Ready when

The default is set deliberately and somebody other than you has agreed it. Both answers are wired, not only the yes. A refusal on first launch results in no events reaching the Edge, and you have watched that happen rather than assumed it.
