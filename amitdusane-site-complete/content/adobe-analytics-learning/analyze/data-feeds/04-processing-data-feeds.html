Working with Data Feeds requires understanding how to parse, join, and analyze the raw data.

Common Processing Steps

ETL Pipeline Example
1. DOWNLOAD & EXTRACT
   - Download files from delivery location
   - Extract from gzip compression
   - Validate manifest file counts

2. PARSE HIT DATA
   - Read hit_data.tsv with column headers
   - Handle tab-delimited format
   - Convert Unix timestamps to datetime

3. JOIN LOOKUP TABLES
   - Match browser IDs to browser names
   - Match geo IDs to country/region names
   - Join custom event names

4. FILTER & CLEAN
   - Remove bot traffic (exclude_hit > 0)
   - Filter test/internal traffic
   - Handle null/empty values

5. TRANSFORM
   - Parse products string into rows
   - Calculate visit-level aggregations
   - Build visitor profiles

6. LOAD
   - Insert into data warehouse
   - Update analytics database
   - Trigger downstream processes

Best Practices

  • Idempotent processing: Design to handle re-processing same files
  • Monitor delivery: Alert on missing or late feeds
  • Validate row counts: Compare to manifest file
  • Archive raw files: Keep originals before processing
  • Handle late data: Adobe may redeliver corrected files
Pro Tip

Create a "visitor_id" column by concatenating visid_high and visid_low. This gives you a unique visitor identifier for joining across hits and building visitor-level tables.

SQL: Create Visitor ID
-- Concatenate visitor ID components
SELECT 
    CONCAT(visid_high, '-', visid_low) as visitor_id,
    visit_num,
    hit_time_gmt,
    post_pagename,
    post_evar1
FROM hit_data
WHERE exclude_hit = 0  -- Exclude bot traffic
