Icon review

Left, what is on the site today. Right, what I suggest. Where an icon already works, it is copied across unchanged.

The one rule behind every suggestion. The site already has an icon language and uses it everywhere except the content components: a 24-unit viewBox, stroke width 2, round caps and joins, one colour. Every chrome icon speaks it, and so does the path tile. The six emoji are the only things that do not — and because the operating system draws them, they are a different picture on Windows, Mac and Android, in colours the site never chose. Column two puts them into the language the site already has.

One-off emoji buried in content

Thirteen glyphs, one use each, scattered inside diagrams and boxes. Nobody learns a vocabulary from a single instance.

1 use each · 13 glyphs
Remove themDelete, or fold into the four tiles above where the meaning already fits
If you take the four tiles. It is one CSS pattern reused four times — a 30px rounded tile, the semantic ink as the fill, a white line glyph at 17px — plus removing the emoji character from 340 component headers. White measures between 5.6:1 and 6.3:1 on all four fills, so every glyph clears the non-text contrast line. It also retires a documented trap: the warning emoji depends on the U+FE0F variation selector, and without it some platforms render a monochrome glyph instead. A tile has no such dependency.
